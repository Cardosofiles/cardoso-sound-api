## 1. O que foi entregue

Entrega do primeiro módulo de domínio completo da API, viabilizando o consumo do catálogo musical pelo app Flutter. Implementa a listagem pública e paginada de artistas (`GET /api/v1/artists` - R04) com busca textual case-insensitive (`ILIKE`) e contagem precisa de faixas, e a consulta detalhada por UUID (`GET /api/v1/artists/:id` - R05) trazendo todas as faixas do artista ordenadas por título (`title ASC`) sem paginação, com embutimento de `ArtistSummary` em cada faixa e conversão canônica de datas para ISO 8601 UTC string.

## 4. Como funciona — o que o diff não conta

1. **Estrutura das 4 Camadas e Conformidade com Boundaries:**
   - `artists.routes.ts` instancia apenas `ArtistsService`. Não importa `src/db/` nem `ArtistsRepository`, assegurando zero violações de boundaries no lint (`eslint-plugin-boundaries`).
   - `ArtistsService` possui injeção por construtor (`constructor(private readonly repo: ArtistsRepository = new ArtistsRepository())`), permitindo que testes unitários injetem dublês em memória (`vi.fn()`) sem necessidade de mock de módulo (`vi.mock`). Zero dependências de Fastify.
   - `ArtistsRepository` injeta a conexão (`constructor(private readonly db: Database = defaultDb)`), viabilizando a injeção do banco efêmero nos testes de integração com Testcontainers.

2. **Cálculo de `trackCount` via Subquery Correlacionada:**
   - A contagem de faixas por artista é resolvida por subquery correlacionada `(SELECT count(*)::int FROM "tracks" WHERE "artist_id" = "artists"."id")`.
   - **Armadilha superada:** Dentro do template literal `sql` do Drizzle ORM, `${artists.id}` emite o identificador não-qualificado `"id"`, que dentro do escopo da subquery `FROM "tracks"` colidiria com a coluna `"tracks"."id"`. A qualificação explícita `${artists}."id"` foi utilizada para referenciar a tabela externa `"artists"`, garantindo contagem correta e preservando o valor `0` para artistas sem faixas.

3. **Reutilização da Cláusula `where` na Paginação:**
   - A mesma instância de `whereClause` é compartilhada entre a query dos registros da página (`.select(...).where(whereClause).limit(...).offset(...)`) e a query de contagem total (`.select({ value: count() }).where(whereClause)`). Isso elimina qualquer risco de divergência matemática nos metadados de paginação (`total`, `totalPages`, `hasNext`, `hasPrev`).

4. **Sanitização de Curingas SQL em `search`:**
   - A busca textual case-insensitive `ILIKE` escapa explicitamente caracteres curinga (`%`, `_`, `\`) utilizando `term.replace(/[%_\\]/g, '\\$&')`. Isso garante que buscas contendo tais caracteres sejam tratadas como literais.

5. **Poda e Imutabilidade de DTOs:**
   - O service mapeia explicitamente as entidades do banco para objetos DTO sem propriedades brutas (`artist_id` ou `artistId` na raiz). O `serializerCompiler` do Fastify Type Provider Zod remove adicionalmente qualquer chave não declarada no schema.

## 6. Armadilhas encontradas

| Sintoma                                                         | Causa                                                                                                           | Solução                                                                                |
| --------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| T13 falhou com `expected +0 to be 5`                            | `${artists.id}` dentro de `sql` subquery gerava `"artist_id" = "id"`, colidindo com `"tracks"."id"` da subquery | Qualificar explicitamente como `${artists}."id"` no Drizzle SQL template               |
| Erro de boundaries no lint: `dto` não pode importar de `config` | `artists.schema.ts` importava constantes de `src/config/constants.ts`                                           | Importar paginação de `src/shared/utils/` e definir `GENRES` localmente                |
| Erro `@typescript-eslint/require-await` em `artistsRoutes`      | Plugin `FastifyPluginAsyncZod` não continha instrução `await` antes dos registros síncronos de rotas            | Inserir `await Promise.resolve();` no início do plugin, espelhando `healthPlugin`      |
| Erros `@typescript-eslint/unbound-method` nos testes unitários  | Referência a métodos mockados em objetos literais (`vi.mocked(repo.list)`)                                      | Extrair mocks para variáveis isoladas (`list = vi.fn()`) antes de montar o objeto repo |
