## 1. O que foi entregue

A API passa a ter seu contrato OpenAPI 3.0.3 formalizado em um artefato versionado (`docs/openapi.json`) e estritamente auditado em pipeline de CI contínua (`.github/workflows/ci.yml`). O script `scripts/export-openapi.ts` foi construído com ordenação recursiva alfabética de chaves JSON para garantir determinismo total (diff zero entre execuções). Foi implementada uma suíte com 12 casos de teste de conformidade (`tests/integration/openapi.test.ts`), e todas as 20 operações Fastify das 14 rotas tiveram seus metadados, resumos e códigos de status complementados.

## 4. Como funciona — o que o diff não conta

1. **Determinismo Absoluto via Ordenação de Chaves:** Em JavaScript, a ordem de propriedades de objetos durante serialização JSON pode variar. A função `sortObjectKeys` varre recursivamente toda a árvore de spec antes de `JSON.stringify`, garantindo que execuções em sistemas operacionais distintos gerem exatamente os mesmos bytes.
2. **Ciclo de Vida do Fastify e Postgres:** `export-openapi.ts` inicializa a aplicação chamando `app.ready()` para montar todas as rotas e plugins, extrai a especificação com `app.swagger()` e encerra a aplicação com `app.close()`. O fechamento do pool de conexões (`pool.end()`) é executado no bloco `finally` da execução direta (`main()`), impedindo que processos em background mantenham o event loop do Node ativo.
3. **Isolamento sem Banco:** Ao definir `process.env.NODE_ENV = 'test'` antes da inicialização, o `@fastify/under-pressure` não dispara o intervalo de checagem do Postgres (`checkDatabase`), viabilizando a exportação e o check do spec mesmo quando o PostgreSQL não estiver em execução.
4. **Tratamento das Rotas do Better Auth:** As rotas sob `/api/auth/*` são delegadas em bloco para o `auth.handler` do Better Auth via Fetch API (D-45) e não possuem schemas Zod do Fastify. Elas foram mantidas transparentes na descrição da API (`info.description`), confirmando que tanto Bearer token quanto Cookie HttpOnly são aceitos para autenticação em toda a API.

## 6. Armadilhas encontradas

| Sintoma                                                                                             | Causa                                                                                                                                    | Solução                                                                                                                                                     |
| --------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `tests/unit/plugins/health.test.ts` falhou em `expect(json.info.title).toBe('cardoso-sound-api')`   | O brief mencionava `title: 'Cardoso Sound API'`, mas a suíte unitária de F1-S06 validava a constante `APP_NAME` (`'cardoso-sound-api'`). | Restaurado `title: APP_NAME` em `swagger.plugin.ts` e re-exportado `docs/openapi.json`.                                                                     |
| `Error: Called end on pool more than once` ao chamar `generateOpenApiSpec()` consecutivamente em T9 | `generateOpenApiSpec` chamava `pool.end()`, destruindo o singleton do pool e quebrando chamadas subsequentes no mesmo processo de teste. | Movido `pool.end()` para o bloco `finally` da função `main()` da CLI, permitindo que a função seja invocada múltiplas vezes em testes sem efeito colateral. |
