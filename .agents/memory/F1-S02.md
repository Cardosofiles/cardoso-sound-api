## 4. Como funciona — o que o diff não conta

### Configuração de Boundaries no ESLint 9

O `eslint-plugin-boundaries` foi configurado diretamente no flat config utilizando a chave `settings['boundaries/elements']`. O mapeamento respeita a matriz de dependência da Clean Architecture de `docs/specs/01-arquitetura.md`:

- `routes`: importa `service`, `dto`, `shared`, `config`
- `service`: importa `repository`, `dto`, `shared`, `config`
- `repository`: importa `db`, `dto`, `shared`, `config`
- `dto`: importa `shared`
- `plugin`: importa `shared`, `config`, `dto`, `db`
- `db`: importa `shared`, `config`
- `shared`: camada folha, importa apenas pacotes externos
- `app`: orquestrador de plugins e rotas
- `server`: bootstrap e shutdown
- `jobs`: background runners

Regra `no-restricted-syntax` garante que `process.env` só seja acessado dentro de `src/config/env.ts`.

### Configuração de Workspace no Vitest

Em vez de depender de herança cega com `extends` (onde o `mergeConfig` do Vite concatenaria padrões de glob do `include`), cada projeto (`unit`, `integration`, `e2e`) define expressamente seu escopo de arquivos (`tests/unit/**/*.test.ts`, etc.), garantindo que `pnpm test` execute exatamente a quantidade esperada de testes e que `--project unit` filtre de forma determinística.
