## 1. O que foi entregue

Criação do núcleo executável e fundação da API `cardoso-sound-api`.
Implementação da hierarquia canônica de erros (`AppError`, `NotFoundError`, `UnauthorizedError`, `ForbiddenError`, `ConflictError`, `ValidationError`) com envelope homogêneo RFC 7807-like.
Configuração do formatador central `errorHandlerPlugin` com `setErrorHandler` e `setNotFoundHandler` via `fastify-plugin`, assegurando que exceções 500 não vazem stack traces nem mensagens internas ao cliente.
Criação da app factory pura `buildApp()` com integração de compiladores Zod e logger estruturado Pino contendo redaction obrigatório de 6 caminhos de dados sensíveis (D-22) e `pino-pretty` restrito a desenvolvimento (D-18).
Bootstrap da aplicação em `server.ts` com tratamento de graceful shutdown para `SIGINT`/`SIGTERM` e timeout defensivo de 10s (`SHUTDOWN_TIMEOUT_MS`).

## 4. Como funciona — o que o diff não conta

1. **Ordem de checagem no `setErrorHandler`:**
   - Primeiro checa `error instanceof AppError` para preservar integridade de erros de domínio lançados pela aplicação.
   - Segundo, utiliza o helper `hasZodFastifySchemaValidationErrors(error)` de `fastify-type-provider-zod` v6. Ele inspeciona o envelopamento interno do Fastify para schemas Zod, extraindo as issues achatadas com status 400.
   - Terceiro, checa se é um erro do Fastify com status 4xx numérico (ex: 429 de rate limit), mapeando status e mensagem amigável sem vazar estruturas internas.
   - Quarto, fallback estrito para 500 com payload fixo `Internal Server Error`, registrando `request.log.error({ err: error })`.
2. **Encapsulamento do Plugin de Erro:**
   - `errorHandlerPlugin` é empacotado com `fastify-plugin` (`fp`), quebrando o encapsulamento de contexto do Fastify para que `setErrorHandler` e `setNotFoundHandler` tenham alcance global sobre todos os plugins e rotas subsequentes.
3. **Redaction do Logger Pino (D-22):**
   - Os 6 caminhos de redaction (`req.headers.authorization`, `req.headers.cookie`, `res.headers["set-cookie"]`, `res.headers["set-auth-token"]`, `*.password`, `*.token`) foram testados e comprovados com substituição direta por `[REDACTED]`.
4. **Shutdown defensivo:**
   - `server.ts` utiliza `forceExitTimer.unref()` com `SHUTDOWN_TIMEOUT_MS` (10s) para garantir que processos travados em `app.close()` não fiquem órfãos em ambientes conteinerizados ou de deploy contínuo.
