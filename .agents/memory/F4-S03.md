## 1. O que foi entregue

Foi implementada e homologada a suíte completa de testes de ponta a ponta (**End-to-End**), cobrindo os 9 fluxos canônicos da Spec 05 §4 (**E1 a E9**) e os casos complementares de reforço (**E10 a E15**). A suíte exercita a API exatamente da mesma forma como o aplicativo Flutter e os clientes web a utilizam: requisições HTTP em memória via `app.inject()` do Fastify atravessando os módulos de autenticação, catálogo público, playlists privadas, favoritos e ciclo de vida da conta com deleção em cascata.

A entrega cumpre rigorosamente a invariante de **zero alterações em código de produção (`src/`)** e atinge tempo de execução de **~20–28 segundos** para o projeto `e2e` (confortavelmente abaixo do teto de 45 segundos da Spec 05 §1). Com este sprint, a **Fase 4 (Biblioteca)** está 100% concluída e a tag `v0.4.0` está apta a ser gerada.

## 4. Como funciona — o que o diff não conta

### Container Singleton no Harness E2E (D-48)

O obstáculo arquitetural central do sprint residia no fato de que `src/db/client.ts` instancia o pool de conexões imediatamente no momento do import, lendo `env.DATABASE_URL`. Além disso, inicializar um container do Testcontainers para cada um dos 5 arquivos de testes E2E multiplicaria o tempo de execução por 5 (~25-30s adicionais de setup Docker), arriscando ultrapassar o teto estrito de 45s estabelecido pela Spec 05 §1.

A solução adotada:

1. `tests/e2e/helpers/app.ts` mantém uma variável de módulo `sharedTestDb: TestDatabase | null`.
2. Como o Vitest executa o workspace `e2e` configurado com `pool: 'forks'` e `singleFork: true` (Decisão D-36), todos os 5 arquivos rodam sequencialmente dentro do mesmo processo worker Node.js.
3. Na primeira chamada de `buildTestApp()`, o container `postgres:17-alpine` sobe via Testcontainers e aplica as migrações de `drizzle/`.
4. O pool singleton global é reconfigurado via `setPool(sharedTestDb.pool)` e `process.env.DATABASE_URL` recebe a connection string do container.
5. Em cada teste individual, o hook `beforeEach` executa `truncateAll(db)` seguido de `seed(db)`, garantindo que cada caso execute com o catálogo completamente populado e as tabelas de usuário, sessões, playlists e favoritos absolutamente limpas.
6. O container é encerrado graciosamente pelo hook `process.once('beforeExit', ...)`.

### Montagem Manual de Cabeçalho Cookie em `app.inject()` (Caso E9)

O utilitário `app.inject()` do Fastify opera em memória e não dispõe de cookie jar automático. No teste E9, a resposta de sign-up emite múltiplos cabeçalhos `Set-Cookie` através do Better Auth. A função `signUpAndGetToken` extrai esses cabeçalhos preservando o array via `res.headers['set-cookie']`, isola o segmento do cookie (descartando metadados de `Path`, `HttpOnly` e `SameSite`) e monta a string enviada na requisição HTTP: `cookie: (Array.isArray(raw) ? raw : [raw]).map((c) => c.split(';')[0]).join('; ')`. O teste prova de forma cabal a coexistência de autenticação por Bearer e Cookie (Decisão D-13).

### Prova Causal de Cascata Relacional no Banco (Caso E8)

Diferente de testes unitários que mockam o banco ou testes superficiais que checam apenas a resposta HTTP, o caso E8 valida fisicamente as tabelas do PostgreSQL após `DELETE /api/v1/me`:

- `db.select().from(user).where(eq(user.id, userId))` -> 0 linhas
- `db.select().from(session).where(eq(session.userId, userId))` -> 0 linhas
- `db.select().from(playlists).where(eq(playlists.userId, userId))` -> 0 linhas
- `db.select().from(playlistTracks).where(...)` -> 0 linhas
- `db.select().from(favorites).where(eq(favorites.userId, userId))` -> 0 linhas
- `db.select().from(tracks)` e `db.select().from(artists)` -> mantêm exatamente 40 faixas e 8 artistas intactos.

## 6. Armadilhas encontradas

| Sintoma                                                           | Causa                                                                         | Solução                                                                                           |
| ----------------------------------------------------------------- | ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| Erros de TS em `tests/e2e/helpers/app.ts` (`Cannot find module`)  | Nível relativo incorreto nos imports de `src/` (2 níveis em vez de 3)         | Ajustado para `../../../src/app.js` e `../../setup/testcontainers.js`.                            |
| Erro ESLint `no-misused-promises` no `process.once('beforeExit')` | Assinatura de `beforeExit` espera retorno `void` e recebia função assíncrona  | Alterado para callback síncrono disparando promise com `.catch()` tratado.                        |
| Erros ESLint `no-non-null-assertion` em arrays dos testes E2E     | Uso de `!` ao acessar primeiro elemento de arrays de retorno                  | Substituído por destructuring seguro e verificação explícita com `if (!item) throw ...`.          |
| Erro ESLint `no-unsafe-assignment` com `expect.any(String)`       | `expect.any()` do Vitest infere tipo `any`, violando regra estrita de tipagem | Utilizado `ErrorResponseEnvelope` tipado com asserção explícita de `typeof message === 'string'`. |
